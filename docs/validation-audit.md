# Аудит: валидация данных на уровне Model

Проверяемый вопрос (единственный пункт задания 5, актуальный на этом этапе):
**есть ли валидация данных на уровне Model, или система доверяет данным из
View?**

Так как код ещё не реализован (реализация — отдельный, не выполнявшийся на
этом этапе пункт практической части), аудит проведён по проектной
документации — по диаграмме классов и описанию взаимодействия слоёв
(`mvc-architecture.md`) — с целью убедиться, что архитектура **закладывает**
проверку данных в правильном месте до того, как будет написан код.

## Результат проверки

| Класс / метод | Где выполняется проверка | Вывод |
|---|---|---|
| `Observation.setValue(v)` | Model | Диапазон значения параметра проверяется внутри самого объекта наблюдения, а не в форме ввода `ObservationEntryForm` |
| `Instrument.checkCalibrationDue()` | Model | Прибор сам определяет просроченность поверки по своим данным, а не по решению Controller |
| `Station.registerInstrument(instr)` | Model | Совместимость прибора со станцией проверяется внутри `Station`, а не при заполнении `StationRegistrationForm` |
| `ObservationEntryForm`, `StationRegistrationForm` (View) | — | Не содержат методов проверки; только собирают ввод и передают его дальше |
| `ObservationController.submitObservation(data)` | — | Не проверяет данные сам: либо получает исключение/отказ от Model и вызывает `ErrorMessageView`, либо получает подтверждение и сохраняет |

## Вывод

По спроектированной архитектуре система **не доверяет данным из View** —
View выступает только источником ввода, а вся содержательная проверка
(диапазоны значений, сроки поверки, совместимость прибора) закреплена за
классами Model через интерфейс `IValidator`. Controller выполняет только
маршрутизацию между View и Model и не принимает решений о корректности
данных.

**Риск для этапа реализации.** Сам факт того, что в проекте есть класс,
реализующий `IValidator`, ещё не гарантирует, что при написании кода
разработчик не продублирует часть проверки в форме ввода "для скорости" —
это стоит отдельно проверить уже на реальном коде, когда он появится (то
есть выполнить оставшиеся пункты задания 5 после реализации системы).
