# Сеть метеорологических станций регионального центра

Учебный проект по МДК 03.01 «Моделирование и анализ ПО», Лабораторная работа №3
«Прямое проектирование: от описания к моделям и коду».

## Что это за система

Информационная система регионального метеорологического центра, которая
координирует работу сети наблюдательных станций (наземных, аэрологических,
морских, автоматических), распределённых по территории. Система должна:

- вести реестр станций и закреплённых за ними приборов;
- принимать результаты наблюдений по расписанию (срочные — каждые 3 часа,
  промежуточные — каждые 6 часов) и учитывать случаи, когда канал связи
  недоступен и данные передаются с задержкой («задержанная передача»);
- выполнять контроль качества поступивших данных (проверку диапазонов,
  сравнение с соседними станциями, выявление выбросов) и возвращать
  подозрительные данные на перепроверку;
- отслеживать сроки поверки приборов, формировать графики поверки и
  фиксировать переход станции на резервный прибор при сбое;
- формировать отчёты для руководителя центра: полнота поступления данных по
  станциям и срокам, количество выбросов и задержанных передач, охват
  приборов поверкой, плотность наблюдений по районам.

## Основные сущности

| Сущность     | Описание                            | Ключевые поля                                                                 |
|--------------|-------------------------------------|-------------------------------------------------------------------------------|
| Станция  | Наблюдательный пункт                | code, name, latitude, longitude, type, status                                 |
| Прибор   | Измерительное средство на станции   | name, type, serial_number, station_id, last_verification, next_verification, status |
| Наблюдение | Результат измерений               | station_id, observation_time, parameters, status                              |
| Передача | Отправка данных в центр             | observation_id, transmission_time, is_delayed                                 |
| Поверка  | Контроль сроков поверки прибора     | device_id, planned_date, status                                               |

## Ключевые сценарии

1. Добавление/редактирование станции и приборов
2. Создание наблюдения и передача данных (с возможностью «задержанной передачи»)
3. Контроль качества (принять / вернуть на перепроверку)
4. Учёт поверок приборов
5. Просмотр простых отчётов

## Роли

| Роль                  | Возможности                              |
|-----------------------|------------------------------------------|
| Наблюдатель           | Создаёт наблюдения и передачи            |
| Оператор центра       | Контроль качества, поверки               |
| Руководитель          | Просмотр отчётов и управление станциями  |

## Основные правила

- У станции должен быть уникальный код
- Прибор принадлежит только одной станции
- Наблюдение нельзя передать без указания станции и времени
- Если данные переданы позже срока — ставится отметка «задержанная передача»
- Прибор должен иметь актуальную дату поверки

## Отчёты

- Полнота поступления данных по станциям
- Количество задержанных передач
- Список приборов с истекающим сроком поверки

## Как она устроена

Проектирование выполняется по архитектурному паттерну **MVC**:

- **Model** — сущности предметной области (станция, прибор, наблюдение,
  поверка, сбой) и вся логика проверки и хранения данных;
- **View** — представление для наблюдателя на станции и для руководителя
  центра (формы ввода наблюдений, списки, отчёты, сообщения об ошибках);
- **Controller** — связующее звено между вводом пользователя и Model.

## Как её запустить

Требования: Python 3.10+ (стандартная библиотека, SQLite). Внешние пакеты
не нужны.

```bash
cd weather_network # каталог клона репозитория

# Интерактивное меню (БД meteo.db создаётся автоматически)
python main.py

# Демонстрация end-to-end на чистой БД
python main.py --demo

# Другой файл БД
python main.py --db my.db
```

## Журнал ключевых решений

| Дата | Решение |
|---|---|
| Этап 1 | Выбрана предметная область «Сеть метеорологических станций регионального центра» |
| Этап 2 | Декомпозиция функциональной модели выполнена на 5 подпроцессов: регистрация станций и приборов → приём и обработка данных → контроль качества → учёт поверки и сбоев → отчётность |
| Этап 3 | Валидация данных наблюдений (диапазоны, статус передачи) закреплена за слоем Model, а не View — Controller только передаёт данные, не проверяя их |
| Этап 4 | Для развязки Model от конкретной реализации хранения и проверки введены интерфейсы `IRepository` и `IValidator` |
